# Code and security audit · November 2026

Staff Portal and public website. Built by cmeproject. (Audited on the first client copy.)

## In short

The portal is in good shape. Every table is locked down by the database
itself, signing in is protected, and there's no way found to inject SQL.
One small gap (a task title readable by ID) was fixed. Browser safety rules
were added. Nothing found needs urgent action from you.

## What was checked

| Area | How | Result |
| --- | --- | --- |
| Database access | Every table on a fresh copy of the database | All 45+ tables have Row Level Security on. The public (not signed in) can only read the settings marked public and the sign-in options. |
| Privileged database functions | Every `security definer` function | All have a fixed `search_path` (stops function hijacking). One, `task_label`, could show a task's title to anyone who knew its ID: **fixed in update 42**. |
| SQL injection | All database calls in the code | The code never builds SQL from text. Everything goes through Supabase's parameterised calls or database functions. The one filter built from a web address (a records page) already required a real record; an extra check was added anyway. |
| Server actions (form submits) | Every action in the code | Each checks who is signed in and what they may do, and the database checks again (two locks on every door). |
| Sign-in | Login, two-factor, apps | 5 wrong passwords lock the email for 15 minutes. Two-factor for chosen roles. App PINs: 5 wrong tries and they must sign in again. Sessions end after inactivity on shared computers. |
| Bots and spam | Website forms and Assistant | Hidden "honeypot" box on the enquiry form, at most 30 enquiries an hour, a questions-per-hour limit and a monthly spending limit on the Assistant. |
| Secrets | Code and settings | Only the Supabase address and public key reach the browser (designed to be public). The service key, AI key and email key stay on the server. |
| Browser safety | Response headers | **Added**: HTTPS only, no showing the portal inside other sites, no file-type guessing, limited referrer details, camera only for this site. |
| Packages | `npm audit` | 8 moderate warnings, all from one library the Excel download uses to zip files (`minimatch` via `archiver`). It only runs on files the portal makes itself, so it can't be triggered from outside. Recheck when exceljs releases an update. |
| Tests | Database test suite | 31 test files, all passing, covering who can see and change what. |

## Changes made in this audit

- `task_label()` can no longer be called directly (update 42).
- Security headers on every page (`next.config.ts`).
- Extra check on the records page filter.
- The website's code split into small, clearly named parts (header, chat history, chat, About page, search-engine details).

## Risks and recommendations

1. **No bot check on the public forms yet.** The limits above stop floods, but a
   free bot check (Cloudflare Turnstile) on Request a call back would stop
   automated spam completely. It needs a free Cloudflare account.
2. **Emails aren't switched on (Resend).** Until then, people only get bell
   notes, not emails (password resets use Supabase's own email).
3. **Supabase settings worth checking** (in the Supabase dashboard, not code):
   leaked-password protection on, minimum password length 10+, and email
   confirmations on.
4. **Backups.** On the free Supabase plan, set up a regular database export,
   or move to Pro for daily backups.
5. **AI key.** Keep the monthly limit in Website settings low to start, and
   watch the usage card in System health.

## For the next developer

- `src/app/(portal)` is the staff portal; `src/app/ask` the public website;
  `src/app/app` and `src/app/cars-app` the phone apps.
- `supabase/migrations` holds every database change in order; each has a
  matching `supabase/live-updates/update-NN.sql` (safe to re-run) and, from
  update 36, an `undo-NN.sql`. `supabase/tests` checks the security rules.
- Restore points (before each big change) are listed in `docs/RESTORE.md`.
- Before pushing: `npm run lint`, `npm run typecheck`, `npm run test:db`.
